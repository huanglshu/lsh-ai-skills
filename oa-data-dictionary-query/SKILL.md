# OA 数据字典表字段查询

## 适用场景

当用户需要查询 OA 系统某张表的字段定义时，执行本技能。典型请求包括：

- `查询 hrmresource 表字段`
- `meeting 表有哪些字段`
- `帮我看一下 workflow_requestbase 的字段说明`

## 输入与预处理

1. 从用户请求中提取表名。
2. 将表名做标准化：
   - 去除首尾空格
   - 转为小写
3. 按标准化后的表名执行后续检索。

## 执行流程

### 1) 定位映射表

读取映射文件：

1. `assets/数据字典/table_mapping.md`

### 2) 从映射表查找目标

1. 在映射表中按“精确表名”查找对应条目。
2. 映射行格式应为：
   - ``- `表名` → 文件名.html``
3. 记录该条目所在模块（由最近的 `#### 模块名` 标题确定）和文件名。

### 3) 生成候选文件路径

用“模块 + 文件名”构建文件路径：

1. `assets/数据字典/{模块}/{文件名}`

### 4) 读取数据字典 HTML

读取命中的 HTML 文件，提取字段定义信息，重点返回：

- 字段名
- 字段类型
- 长度/精度
- 是否可空（若有）
- 默认值（若有）
- 字段说明

如果页面结构存在差异，至少返回可稳定提取的“字段名 + 字段说明”。

## 输出规范

默认按以下结构返回：

1. 表名（标准化前/后）
2. 所属模块
3. 命中文件路径
4. 字段清单（表格或清晰列表）
5. 提取说明（例如“长度列在原文缺失”）

优先使用表格输出字段清单；如果列不齐全，改为列表并标注缺失项。

## 错误处理

### 表名不存在

当映射表中找不到表名时，返回：

`未找到表 {表名} 的数据字典信息，请确认表名是否正确。`

并附加相近建议（如可用）：

- 使用前缀匹配（例如输入 `hrmres` 时建议 `hrmresource`）
- 使用包含匹配（例如输入 `meeting` 时返回若干候选）

### 文件不存在

映射命中但文件路径不存在时，返回：

`数据字典文件不存在：{文件路径}`

并继续尝试其他候选路径；全部失败后再最终报错。

## 模块范围

本技能支持以下模块分类（以映射表实际内容为准）：

- 人力资源
- 会议管理
- 公共组件(前端组件+e9消息中心)
- 其他
- 协作管理
- 工作微博
- 工作流程
- 文档管理
- 日程管理
- 流程管理
- 知识管理

## 示例

### 示例 1

输入：`查询 hrmresource 表的字段`

处理：

1. 标准化：`hrmresource`
2. 映射命中：`hrmresource(人力资源基本信息表).html`
3. 定位文件：`数据字典/人力资源/hrmresource(人力资源基本信息表).html`
4. 读取并返回字段信息

### 示例 2

输入：`meeting 表有哪些字段`

处理：

1. 标准化：`meeting`
2. 映射命中：`meeting(会议管理表详细信息).html`
3. 定位文件：`数据字典/会议管理/meeting(会议管理表详细信息).html`
4. 读取并返回字段信息

## 实施建议

1. 缓存 `table_mapping.md` 解析结果，避免重复扫描。
2. 精确匹配失败时，自动回退到模糊匹配并给出候选。
3. 用户一次给出多个表名时，支持批量查询并分段输出。
4. 当 HTML 较大时，优先提取字段表主体，避免整页回传。
